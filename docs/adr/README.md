# Architectural decision records

Long-lived architectural decisions live here.

An ADR should capture a decision that is useful to preserve after the
implementation has moved on. Keep it concise:

1. **Context** — what problem or constraint forced a decision?
2. **Decision** — what was chosen?
3. **Consequences** — what follows from that choice?
4. **Alternatives considered** — what was deliberately not chosen?

ADRs are project history and design records, not replacements for the
architecture chapter. The compiled guide does not include this directory in
its reader-facing contents.
